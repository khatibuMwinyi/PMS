  <action>
    Add to queries.ts (use 'use server'):
    - checkAuditIntegrity(): Scans for integrity issues:
      1. Orphaned events: AuditEvent with entityType='Dispute' but no Dispute with that ID
      2. Missing events: Dispute created but no CREATE event found
      3. Inconsistent status: Dispute status='RESOLVED' but no RESOLVED audit event
      4. Returns: { issues: Array<{ type: string, entityType: string, entityId: string, description: string }>, healthy: boolean }
    - verifyRetention(retentionDays: number = 365): Checks old audit events:
      1. Find AuditEvent records older than retentionDays
      2. Group by entityType, count events eligible for archival
      3. Returns: { eligibleCount, byEntityType: Record<string, number>, recommendedAction: 'ARCHIVE' | 'DELETE' }
    - getAuditReport(startDate, endDate): Generates report:
      1. Count events by entityType, action, date range
      2. Include dispute-related events, utility events, wallet events
      3. Returns: { totalEvents, byEntityType, byAction, timeSeriesData }

    Create AuditIntegrityChecker.tsx (Server Component):
    - Calls checkAuditIntegrity on load
    - Displays: integrity status (healthy/issues found), list of issues with details
    - "Run Check" button to re-verify
    - Color-coded: green for healthy, red for issues

    Create RetentionVerifier.tsx (Server Component):
    - Calls verifyRetention with configurable retention period
    - Displays: eligible count, breakdown by entity type
    - "Archive Old Events" button (placeholder for future)
    - Warning if >1000 events eligible

    Create AuditReport.tsx (Server Component):
    - Date range picker (start/end)
    - Calls getAuditReport with selected range
    - Displays: total events, breakdown charts (use CSS bars)
    - Export as JSON button

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-22 | Spoofing | Audit integrity check | mitigate | Admin-only access via requireRole('ADMIN'). Integrity check reads only, no modifications. |
| T-04-23 | Tampering | Audit events | mitigate | AuditEvent model is append-only (no update/delete actions exposed). Integrity checker detects tampering attempts. |
| T-04-24 | Repudiation | Audit logging | mitigate | All Phase 4 actions log to AuditEvent with actorId, timestamp, old/new values. Integrity checker verifies logs match state. |
| T-04-25 | Information Disclosure | Audit report | mitigate | Admin-only access to audit pages. Report shows summaries only (not raw PII). Export JSON for admin use only. |
| T-04-26 | Denial of Service | Audit integrity job | accept | Weekly job, lightweight read-only queries. No performance impact. |
| T-04-27 | Elevation of Privilege | Production access | mitigate | Production readiness checklist includes verifying all role guards in place. No privilege escalation paths. |
</threat_model>
