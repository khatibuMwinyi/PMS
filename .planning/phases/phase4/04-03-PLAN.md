  <name>task 1: Analytics Query Modules</name>
  <files>src/features/analytics/types.ts, src/features/analytics/queries.ts</files>
  <action>
    Create types.ts with TypeScript types (no Zod needed for queries):

    OwnerAnalytics:
    - totalServiceSpend: Decimal (sum of all completed service payments)
    - totalUtilitySpend: Decimal (from utility bills via 04-02 queries)
    - totalPropertyCost: Decimal (service + utility spend)
    - activeServices: number (active agreements count)
    - serviceSpendByMonth: Array<{ month: string, amount: Decimal }>
    - utilitySpendByMonth: Array<{ month: string, amount: Decimal }>
    - propertyCostBreakdown: Array<{ propertyName: string, serviceCost: Decimal, utilityCost: Decimal, total: Decimal }>

    ProviderAnalytics:
    - totalEarnings: Decimal (sum of completed payments to provider)
    - pendingEarnings: Decimal (in pending wallet balance)
    - completionRate: number (completed/total assigned * 100)
    - upcomingWork: Array<{ taskId, propertyName, scheduledDate, status }>
    - earningsByMonth: Array<{ month: string, amount: Decimal }>
    - recentTransactions: Array<{ date, description, amount, type }>

    AdminAnalytics:
    - totalRevenue: Decimal (platform fees from all transactions)
    - disputeBacklog: number (open + under_review disputes count)
    - providerStrikes: Array<{ providerName, strikeCount, status }>
    - revenueByMonth: Array<{ month: string, amount: Decimal }>
    - disputeTrend: Array<{ month: string, opened: number, resolved: number }>
    - topProviders: Array<{ providerName, earnings, completionRate, strikes }>

    Create queries.ts with 'use server' directive:

    getOwnerAnalytics(ownerId):
    - Fetch totalServiceSpend from Agreement + Payment records
    - Fetch totalUtilitySpend using getTotalUtilitySpend from 04-02
    - Calculate totalPropertyCost = serviceSpend + utilitySpend
    - Count activeServices (agreements with status=ACTIVE)
    - Build monthly breakdowns using Prisma groupBy
    - Return OwnerAnalytics object

    getProviderAnalytics(providerId):
    - Fetch totalEarnings from wallet transactions (where type=CREDIT)
    - Get pendingEarnings from Wallet.pending balance
    - Calculate completionRate: (completed tasks / total assigned) * 100
    - Fetch upcomingWork from Task where providerId and status=SCHEDULED/IN_PROGRESS
    - Build earningsByMonth from wallet transactions
    - Return ProviderAnalytics object

    getAdminAnalytics():
    - Calculate totalRevenue from platform fees (20% of all payments)
    - Get disputeBacklog count from Dispute model (status=OPEN or UNDER_REVIEW)
    - Fetch providerStrikes with provider names and strike counts
    - Build revenueByMonth from payment records
    - Build disputeTrend from Dispute createdAt and resolvedAt
    - Get topProviders by earnings with completion rate and strikes
    - Return AdminAnalytics object

    Helper function: getMonthlyBreakdown(prismaModel, dateField, amountField, startDate, endDate)
    - Uses Prisma groupBy with _sum and _count
    - Returns array formatted for charts
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner → Analytics | Owner views own property spending only |
| Provider → Analytics | Provider views own earnings and performance |
| Admin → Analytics | Admin views platform-wide metrics |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-12 | Spoofing | Owner analytics | mitigate | Validate ownerId from session. Query only agreements/properties where ownerId matches. Use requireRole('OWNER'). |
| T-04-13 | Spoofing | Provider analytics | mitigate | Validate providerId from session. Query only tasks/wallet where providerId matches. Use requireRole('PROVIDER'). |
| T-04-14 | Information Disclosure | Admin analytics | mitigate | Admin role check via requireRole('ADMIN'). All queries scoped properly. No cross-tenant data leakage. |
| T-04-15 | Tampering | Analytics data | accept | Read-only queries (no mutations). Data comes from aggregated queries, not user input. |
| T-04-16 | Repudiation | Analytics access | mitigate | Analytics page views logged via existing AuditEvent (entityType=PAGE_VIEW, entityId=analytics). Low priority, sample implementation. |
</threat_model>
