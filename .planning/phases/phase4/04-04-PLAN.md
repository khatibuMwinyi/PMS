  <files>src/core/events/handlers/report-events.ts, src/features/notifications/actions.ts, src/features/analytics/queries.ts</files>

    Create report-events.ts event handler:
    - Export async function generateMonthlyReports(month: Date, year: Date):
      1. Get all owners: prisma.user.findMany({ where: { role: 'OWNER' } })
      2. For each owner: generate OwnerMonthlyReport (call getOwnerAnalytics)
      3. Create notification: MONTHLY_SUMMARY_OWNER with report payload
      4. Get all providers: prisma.user.findMany({ where: { role: 'PROVIDER' } })
      5. For each provider: generate ProviderMonthlyReport (call getProviderAnalytics)
      6. Create notification: MONTHLY_SUMMARY_PROVIDER with report payload
      7. Generate AdminMonthlyReport (call getAdminAnalytics)
      8. Create notification: MONTHLY_SUMMARY_ADMIN with platform metrics

    Monthly Report Payload Structure (JSON):
    - Owner: { totalServiceSpend, totalUtilitySpend, totalPropertyCost, activeServices, topProperty, month, year }
    - Provider: { totalEarnings, completionRate, totalTasks, upcomingCount, month, year }
    - Admin: { totalRevenue, totalDisputes, resolvedDisputes, activeProviders, month, year }

    Update notifications/actions.ts:
    - Add sendMonthlySummary(userId, role, month, year, reportData):
      Creates in-app notification with type MONTHLY_SUMMARY_*
      Payload contains serialized report data
    - Add markAsRead(notificationId): User marks notification as read

    Create pg-boss scheduled job in src/core/jobs/boss.ts:
    - Name: 'monthly-report-generation'
    - Schedule: cron '0 9 1 * *' (9 AM on 1st of each month)
    - Handler: calls generateMonthlyReports for previous month

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dispute Resolution → Notifications | System sends notifications to both parties |
| Monthly Reports → Users | Automated reports sent to all roles |
| Notification Bell → User | User views own notifications only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-17 | Spoofing | Notification recipients | mitigate | Notifications scoped to userId. User can only see their own notifications. Use requireRole for role-specific reports. |
| T-04-18 | Tampering | Notification content | mitigate | Notification payload stored as JSON in DB. Generated server-side from analytics queries. Client cannot modify. |
| T-04-19 | Information Disclosure | Monthly reports | mitigate | Owner sees only own data. Provider sees only own earnings. Admin sees platform-wide (appropriate). Use existing query scoping. |
| T-04-20 | Repudiation | Notification sends | mitigate | Notification creation logged to AuditEvent: entityType=Notification, action=CREATE. Include payload summary in newValue. |
| T-04-21 | Denial of Service | Notification polling | accept | Polling every 60s is low frequency. Rate limited by existing rate limiter. Bell badge cached client-side. |
</threat_model>
